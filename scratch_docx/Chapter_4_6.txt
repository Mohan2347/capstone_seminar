## CHAPTER 4: PROBLEM ANALYSIS

### 4.1 PRODUCT DEFINITION
InternAI Compass is an intelligent, full-stack web application engineered to bridge the gap between academic preparation and professional internship opportunities. The product is defined by its ability to transform unstructured student data into actionable career pathways using a multi-layered AI architecture. Unlike traditional job portals, InternAI Compass acts as an "Intelligent Career Navigator."

The product consists of:
- **A Unified Web Portal**: Built with Next.js 15, providing high-performance interfaces for students, employers, and administrators.
- **The SmartMatch-AI Engine**: A hybrid recommendation microservice that utilizes transformer-based NLP (BERT), collaborative filtering, and reinforcement learning.
- **Blockchain Verification Layer**: A cryptographic hashing system that ensures the authenticity of employer postings and student credentials.
- **Predictive Analytics Suite**: Dashboards that visualize skill gaps, industry trends, and employability scores.

The product's core value proposition is "Precision, Personalization, and Trust." It aims to reduce the time-to-placement for students while increasing the quality of talent acquisition for employers.

### 4.2 FEASIBILITY ANALYSIS

**4.2.1 TECHNICAL FEASIBILITY**
The technical feasibility of InternAI Compass is supported by the maturity of the underlying technologies:
- **AI/ML**: Pre-trained transformer models like BERT are readily available via libraries like HuggingFace. Implementing hybrid recommendation logic (Content + Collaborative) is a well-documented process in data science.
- **Full-Stack Development**: Next.js 15 is a robust framework that handles both frontend rendering and backend API orchestration efficiently.
- **Data Management**: Serverless PostgreSQL (NeonDB) and Prisma ORM provide a scalable and type-safe data environment.
- **Blockchain**: Implementing cryptographic hashing (SHA-256) for data integrity is technically straightforward and does not require a full, expensive decentralized network for the initial prototype.
- **Microservices**: Using Python FastAPI to serve AI models allows for clean decoupling of the heavy computation from the user interface logic.
The availability of these tools and the extensive documentation surrounding them make the project highly feasible from a technical standpoint.

**4.2.2 ECONOMIC FEASIBILITY**
The project is economically feasible due to the "Lean Startup" approach applied to its development:
- **Development Costs**: The initial development utilizes open-source libraries and frameworks (React, Next.js, FastAPI, Transformers).
- **Hosting and Infrastructure**: The project leverages the free and professional tiers of serverless platforms like Vercel (frontend) and NeonDB (database), minimizing upfront infrastructure investment.
- **API Costs**: While advanced AI features may use third-party APIs (like Gemini), the SmartMatch-AI core is designed to run on local compute instances to manage costs.
- **Market Value**: For universities, the system reduces the manual labor of placement cells. For employers, it reduces the cost of "bad hires." This clear ROI (Return on Investment) makes the product economically attractive for future institutional adoption.

**4.2.3 OPERATIONAL FEASIBILITY**
Operational feasibility is ensured by focusing on the user experience (UX) of all stakeholders:
- **For Students**: The platform is designed to be as simple as a social media app. One-click resume uploads and intuitive "Match Scores" mean no training is required.
- **For Administrators**: The analytics dashboards translate complex AI data into simple bar charts and radar graphs, allowing placement officers to make decisions without needing a data science degree.
- **For Employers**: The blockchain verification process is automated, requiring only a one-time credential submission. The ranked candidate lists save recruiters hours of manual screening.
The system integrates seamlessly into existing university placement workflows, ensuring high adoption rates and low resistance to change.

### 5.1 INTRODUCTION
Software Requirement Analysis (SRA) is the process of defining the expectations of the users for a new or modified software product. For InternAI Compass, this process involved translating the broad vision of a career navigator into a specific set of technical specifications. The analysis focused on three pillars: intelligence (AI), security (Blockchain), and usability (UI/UX).

### 5.2 GENERAL DESCRIPTION
InternAI Compass is a multi-user, web-based platform. It operates by analyzing multidimensional student profiles against a verified database of internship opportunities. The system's general workflow includes profile creation (via resume parsing), intelligent recommendation generation (via SmartMatch-AI), interaction capturing (for reinforcement learning), and data validation (via blockchain). The system is designed to be high-performing, secure, and accessible from any device with a modern web browser.

### 5.3 SPECIFIC REQUIREMENTS

**5.3.1 FUNCTIONAL REQUIREMENTS**
- **FR1: Account Management**: The system shall support secure registration and profile management for three roles: Student, Employer, and Admin.
- **FR2: Resume Parsing**: The system shall be able to extract text from PDF resumes and identify key entities such as skills, education, and experience.
- **FR3: Semantic Embedding**: The system shall use BERT to convert text data into 768-dimensional vector embeddings for deep contextual analysis.
- **FR4: Hybrid Recommendation**: The system shall compute a compatibility score for every student-internship pair using both content-based and collaborative filters.
- **FR5: Blockchain Verification**: The system shall generate a SHA-256 hash for every internship posting to ensure its authenticity.
- **FR6: Feedback Processing**: The system shall capture user interactions (Click, Like, Apply) and update the recommendation weights using reinforcement learning.
- **FR7: Analytics Dashboard**: The system shall visualize skill gaps and employability scores for students and cohort trends for administrators.

- **NFR1: Performance**: The system shall generate recommendations and load pages in under 1.5 seconds.

- **NFR4: Usability**: The system shall maintain a "clean" and "intuitive" UI, scoring at least 80% on standard usability surveys.
- **NFR5: Compatibility**: The system shall be compatible with the latest versions of Chrome, Firefox, Edge, and Safari.

**5.3.3 SYSTEM REQUIREMENTS**
- **Hardware**: Any modern PC or smartphone. Servers require at least 8GB RAM and 4-core CPUs for the AI microservice.
- **Software**: Modern Web Browser, Node.js 18+ (for development), Python 3.9+ (for AI services).
- **External APIs**: Clerk (Auth), NeonDB (PostgreSQL), Gemini (Advanced NLP).

## CHAPTER 6: DESIGN

### 6.1 SYSTEM DESIGN
The InternAI Compass system design follows a **Modular Microservices Architecture** to ensure flexibility, scalability, and ease of maintenance. The architecture is divided into four main layers:

1.  **Presentation Layer (Frontend)**: Developed using **Next.js 15 (App Router)** and **React**. This layer handles the user interface, state management, and real-time data visualization.
2.  **API Orchestration Layer (Backend)**: Uses Next.js API Routes (Node.js) to manage business logic, authentication, and communication between the frontend and the database.
3.  **Data Layer**: Utilizes **PostgreSQL** hosted on **NeonDB** for persistence. **Prisma ORM** provides the type-safe data access layer.
4.  **Intelligence Layer (AI Microservice)**: A standalone **Python FastAPI** service that runs the SmartMatch-AI algorithm. It communicates with the backend via RESTful APIs, handling BERT embeddings and reinforcement learning updates.

### 6.2 DATABASE DESIGN
The database design is centered on a highly relational schema to capture the complex connections between students, skills, and employers.

**Key Entities**:
- **User (Clerk ID)**: The central identity for all actors.
- **Student Profile**: Links to the User, storing resume content, skill vectors, and career aspirations.
- **Employer**: Stores company details and blockchain verification status.
- **Internship**: Stores role descriptions, requirements, and the cryptographic hash.
- **Interaction/Feedback**: A many-to-many table linking Students to Internships, storing action types (Apply, Ignore) and reward values for the RL model.
- **Skill Map**: A lookup table of industry-standard competencies.

### 6.3 DESIGN NOTATIONS
- **TypeScript**: Used throughout the frontend and backend for strict type-safety, reducing runtime errors.
- **JSON**: The primary data format for API communication between the Next.js backend and Python AI service.
- **Tailwind CSS**: Used for the design system, ensuring a consistent, responsive, and professional UI.
- **Prisma Schema**: The "Source of Truth" for the database structure.

### 6.4 DETAILED DESIGN

**The SmartMatch-AI Algorithm Design**:
The algorithm computes a final match score `S` using the formula:
`S = (alpha * Sc) + ((1 - alpha) * Sb)`
- `Sc`: Content-Based Similarity (Cosine similarity of BERT vectors).
- `Sb`: Behavioral/Collaborative Similarity (Based on similar user actions).
- `alpha`: The adaptive weight parameter.

**Reinforcement Learning Loop**:
The system uses a feedback mechanism to update `alpha`. When a user applies for an internship, it's a positive reward (+1). When they reject a highly-ranked role, it's a negative penalty (-1). The weight is updated using:
`alpha = alpha + learning_rate * (Reward - Predicted_Value)`

**Blockchain Verification Hashing**:
To ensure data integrity, the system performs the following during internship submission:
1.  Concatenate: `EmployerID + RoleName + Description + Timestamp`.
2.  Generate SHA-256 Hash.
3.  Store Hash in the database and display the verification badge.
4.  Periodically re-calculate the hash to ensure no unauthorized database edits have occurred.

### 6.5 FLOWCHARTS
The system workflow follows this logic:
1.  **User Onboarding**: User logs in -> Uploads Resume -> System parses text -> Python service generates BERT embeddings -> Vectors stored in PostgreSQL.
2.  **Employer Posting**: Employer posts role -> System generates SHA-256 hash -> Verification status updated -> Role becomes searchable.
3.  **Recommendation Phase**: System triggers SmartMatch-AI -> Calculates hybrid scores for all verified roles -> Ranks and displays to student.
4.  **Feedback Phase**: Student clicks "Apply" -> Reward signal sent to Python service -> Alpha weight adjusted -> Future rankings reflect the new preference.

### 6.6 PSEUDO CODE
```text
ALGORITHM: SmartMatch_AI_Recommendation
INPUT: student_id, internship_list
OUTPUT: ranked_recommendations

1. student_profile = FETCH_PROFILE(student_id)
2. student_vector = student_profile.embedding
3. alpha = student_profile.alpha_weight

4. FOR EACH internship IN internship_list:
    IF NOT internship.is_verified: CONTINUE
    
    job_vector = internship.embedding
    
    // Calculate Semantic Alignment
    content_score = COSINE_SIMILARITY(student_vector, job_vector)
    
    // Calculate Behavioral Alignment (Collaborative Filtering)
    collab_score = COMPUTE_CLUSTER_PREFERENCE(student_id, internship.category)
    
    // Calculate Final Hybrid Score
    final_score = (alpha * content_score) + ((1 - alpha) * collab_score)
    internship.temp_score = final_score

5. ranked_list = SORT_DESCENDING(internship_list BY temp_score)
6. RETURN ranked_list


ALGORITHM: Reinforcement_Learning_Update
INPUT: student_id, action_type, predicted_score

1. reward = 1.0 IF action_type == 'APPLY' ELSE -1.0
2. alpha = FETCH_ALPHA(student_id)
3. eta = 0.01 // Learning Rate
4. new_alpha = alpha + eta * (reward - predicted_score)
5. new_alpha = CLAMP(new_alpha, 0.2, 0.8) // Ensure balance
6. UPDATE_ALPHA(student_id, new_alpha)
```
